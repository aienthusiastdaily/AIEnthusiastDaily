I wanted to give the agent real freedom to work: inspect a task, create scripts, run them, and revise the approach inside a controlled sandbox. The harness should constrain where the work happens and what counts as acceptable—not prescribe one fixed recipe. Its stable interfaces push the agent toward reusable solution shapes instead of one-off answers.

What I built

The custom loop gives one generic agent broad latitude inside the sandbox. It can choose an approach, write and run task-specific code, inspect the result, and try again. Google ADK supplies the agent framework underneath, and GPT-5.6 Terra was the model used for this recorded run. Model choice sits behind the runtime boundary, so the host lifecycle is designed to remain model-agnostic; the harness supplies the stable lifecycle, capability boundaries, and evidence contract around that work.

Task knowledge lives in a versioned solution layer: activated skills, task adapters, acceptance contracts, and allowed tools. That separation lets the root agent and host lifecycle remain stable while a task solution becomes more capable. Generated code stays inside an isolated sandbox with host-enforced boundaries, and only work that passes the host's acceptance contract can cross into durable state.

Designed evolution loop Keep the harness stable. Let the solution layer improve.
01 A new task variant appears
02 The agent can propose and test a new approach
03 The host can validate the evidence
04 The agent could reconcile new and existing approaches into a more generalizable skill or adapter

This recording demonstrates the author–run–validate loop. Continuous cross-run updating is the next design layer: after the host validates a new approach, the agent would compare it with existing patterns, reconcile their shared logic and useful differences, and propose a more generalizable versioned skill or adapter. That update would still need host review and regression evidence before future agents inherit it.

The long-term target is not one scraper. It is a reliable, reusable, generalizable, and secure agentic workflow for any task that can be expressed through a skill, allowed tools, an acceptance contract, and an evidence interface—then continuously updated through host-reviewed versions. This recording proves the loop for one job-listing task, not that universal reach.

The boundary of the claim

This demonstrates one production-oriented control loop on one frozen synthetic layout modeled on a job listing. It does not prove broad coverage across tasks or websites. Portability is a design claim that the later parts of this series will test rather than assume.
